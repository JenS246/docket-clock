# Docket Clock

Docket Clock is a responsive guessing game for civil litigation and paralegal students. Every active round starts with the initial complaint and asks the player to estimate the time to a major decision or final resolution. The reveal explains the full measured interval, shows the procedural timeline, awards a proportional score, and links to the supporting sources.

## Public site

- Website: https://jens246.github.io/docket-clock/
- Source: https://github.com/JenS246/docket-clock
- Backend: none. The game is a static site and stores only recently shown case IDs in the player’s browser.

## Features

- Five-case and ten-case games
- Twelve game categories with recognizable-case defaults
- Complaint-first gameplay that exposes the years hidden before a famous ruling or settlement
- Touch, mouse, and keyboard-friendly month slider
- Proportional scoring and direct accuracy feedback
- Exact date reveal, timeline, outcome, litigation note, and source links
- End-of-game statistics and answer-free result sharing
- Local recent-case tracking to reduce repetition
- Searchable case explorer
- In-browser JSON and CSV import validator
- Light and dark color schemes, visible focus states, and reduced-motion support

## Case bank

[`data/cases.json`](data/cases.json) contains 220 sourced intervals. The active game draws only from records whose exact `initialFilingDate` matches the measured start date. Older appellate-only intervals remain available in the explorer for comparison but cannot enter a game. Every shipped record is marked `Verified`, has at least two dated events, and includes supporting links. The current bank mixes U.S. Supreme Court, federal appellate, federal trial, and state-court matters. Separate intervals from the same litigation share a `litigationId`, and the selector prevents them from appearing in one game.

The complaint-first collection includes nationally recognizable disputes such as the O.J. Simpson civil case, the McDonald's hot-coffee case, Depp v. Heard, the Sandy Hook litigation, the George Floyd and Breonna Taylor family cases, New York's civil-fraud case against Donald Trump, Flint Water, Equifax, Enron, JUUL, Hulk Hogan v. Gawker, Taylor Swift's radio-host trial, and Johansson v. Disney. These sit alongside longer-running institutional, civil-rights, technology, environmental, and mass-tort cases so the game shows both unusually fast settlements and proceedings that consumed many years.

The bank is generated by [`scripts/build-case-bank.mjs`](scripts/build-case-bank.mjs) from public Oyez metadata, selected legal-case pages, and the source-checked familiar cases in [`data/curated-filing-cases.json`](data/curated-filing-cases.json). Curated records take precedence over automatically sourced duplicates. Generation never invents missing dates. Records without a complete, chronological, exact-date interval are omitted.

To rebuild the bank:

```bash
npm run data:build
npm test
```

The upstream services may throttle large metadata requests. The builder retries transient failures and safely skips a throttled subject category while still enforcing the 200-record minimum.

## Add or edit cases

The content layer is separate from the interface. Add records directly to `data/cases.json`, regenerate the file with the builder, or use the Case Data Manager in the site to validate a `.json` or `.csv` import before merging it.

Required fields include the case and litigation IDs, exact initial complaint and endpoint dates, calculated month count, events, courts, outcome, teaching note, sources, familiarity, verification status, and review date. Only `Verified` complaint-first records enter gameplay.

The validator flags:

- Missing or malformed dates and events
- Reversed chronology or incorrect elapsed-month calculations
- Duplicate IDs and duplicate playable intervals
- Missing timelines, courts, sources, or familiarity ratings
- Records not marked `Verified`

## Run locally

Requires Node.js 22 or newer.

```bash
npm install
npm run dev
```

Open the local URL printed by the development server. Common checks are:

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run build:pages
```

## Deployment

The GitHub Actions workflow at [`.github/workflows/pages.yml`](.github/workflows/pages.yml) tests the project, produces a static Next.js export with the `/docket-clock` base path, and deploys the `out` directory to GitHub Pages after each push to `main`.

No environment variables, credentials, database, or backup procedure are required. The source JSON is the durable data store and is backed up in Git.
